## What it is

Slayply lives in Chrome's side panel. On a job page, you capture the description and the questions. It checks how well you fit, picks the right résumé, and drafts answers, a cover letter or a message. You bring your own key for Claude, OpenAI or Gemini.

It never fills in or submits anything. You read, edit, copy and submit yourself, every time.

## Why I built it

Job applications ask the same questions in slightly different words, and generic AI drafts read like generic AI drafts. Worse, they invent things: a metric you never hit, a tool you never used. I wanted drafts that can't.

## The idea that matters: claim checking

You keep one profile of real facts, and each fact has an ID. Every sentence the model writes about you has to cite one. A deterministic checker then highlights any sentence with no citation, so an invented claim is flagged before it reaches an application.

It's a monorepo with six packages: the extension, the relay, a static site, a shared core, the provider adapters and a UI kit. Your profile, résumés and keys stay in the browser. The relay keeps nothing, and there is no telemetry.

## How I built it

I wrote the spec and the architecture decisions first, then worked with coding agents inside a harness: a handoff pointer file the agent reads at the start of every session, tests written before the change, and hooks that block risky actions. I describe the whole setup in [How I use AI in my production workflow](/logs/how-i-use-ai-in-my-production-workflow).

## Where it stands

It has had one real-world test: answer generation worked end to end with a real Gemini key, slowly. A fit check on a slow thinking model ran past the relay's time limit, and I've added progress and retry for it. The Claude and OpenAI paths were written from the vendors' documentation and haven't been run live. If you have credits and ten spare minutes, an [issue](https://github.com/devnadeemashraf/slayply/issues/new) saying what broke, or that it worked, helps a lot.

## What I'd change

I'd test against real providers earlier. Almost everything is verified with stubs, which proves the plumbing and says nothing about how real models behave on real job pages.
